## 1. インシデント分類

### 1.1 CareQuest特有の重大度

| 重大度 | CareQuest定義 | 例 | 対応時間 |
|--------|--------------|-----|---------|
| **SEV1** | **ケア記録の損失・破損** | DynamoDB書込失敗、データ消失 | **即時** |
| SEV2 | 記録機能の完全停止 | API Gateway 5xx多発 | 1時間以内 |
| SEV3 | 一部機能障害 | 履歴参照のみ不可 | 4時間以内 |
| SEV4 | 軽微な問題 | 通知遅延 | 次営業日 |

> **最重要:** SEV1は介護事故・コンプライアンスリスクに直結。
> 耐久性SLO 99.9%違反は即座にSEV1として扱う。

### 2.2 CQ-01: ケア記録書込失敗

**検知:**
```bash
# CloudWatch Metrics
aws cloudwatch get-metric-statistics \
  --namespace AWS/DynamoDB \
  --metric-name WriteThrottleEvents \
  --dimensions Name=TableName,Value=carequest-records \
  --start-time $(date -u -v-1H +%Y-%m-%dT%H:%M:%SZ) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%SZ) \
  --period 300 \
  --statistics Sum
```

**対応フロー:**
```
WriteThrottleEvents > 0 検知
    │
    ▼
┌─────────────────────┐
│ 1. 影響範囲確認      │ ← どの施設の記録が失敗したか
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 2. 原因切り分け      │
│  - スループット超過  │ → Auto Scaling確認
│  - ネットワーク障害  │ → VPC/Endpoint確認
│  - コードバグ        │ → Lambda ログ確認
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 3. 即時対応          │
│  - スループット増強  │
│  - ロールバック      │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 4. データ復旧        │ ← PITR使用（RB-0001）
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 5. 施設への連絡      │ ← 影響施設に個別連絡
└─────────────────────┘
```

**復旧コマンド:**
```bash
# DynamoDB PITR復旧
<私有リポジトリの運用スクリプト>/dynamodb-pitr-restore.sh \
  carequest-records \
  "$(date -u -v-1H +%Y-%m-%dT%H:%M:%SZ)"
```

           │

           │
           ▼

│ 4. PITR復旧          │ ← 破損前時点へ
└──────────┬──────────┘
           │
           ▼

### 2.4 CQ-03: 認証失敗（ログイン不可）

**検知:**
```bash
# Cognito Metrics
aws cloudwatch get-metric-statistics \
  --namespace AWS/Cognito \
  --metric-name SignInThrottles \
  --dimensions Name=UserPool,Value=<user-pool-id> \
  --start-time $(date -u -v-1H +%Y-%m-%dT%H:%M:%SZ) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%SZ) \
  --period 300 \
  --statistics Sum
```

**対応フロー:**
| 原因 | 確認方法 | 対応 |
|------|---------|------|
| Cognitoサービス障害 | AWS Status Page | 待機 + ユーザー連絡 |
| User Pool設定誤り | コンソール確認 | 設定修正 |
| Client Secret不一致 | アプリ設定確認 | シークレット再設定 |
| トークン有効期限切れ | ログ確認 | リフレッシュ誘導 |

### 2.5 CQ-04: API Gateway 5xx多発

**検知:**
```bash
# API Gateway 5xx
aws cloudwatch get-metric-statistics \
  --namespace AWS/ApiGateway \
  --metric-name 5XXError \
  --dimensions Name=ApiName,Value=carequest-api \
  --start-time $(date -u -v-15M +%Y-%m-%dT%H:%M:%SZ) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%SZ) \
  --period 60 \
  --statistics Sum
```

**対応フロー:**
```
5XXError > 10/min 検知
    │
    ▼
┌─────────────────────┐
│ 1. Lambda ログ確認   │
└──────────┬──────────┘
           │
           ├── Timeout → メモリ/タイムアウト増強
           │
           ├── Throttle → 同時実行数制限確認
           │
           └── Code Error → ロールバック
```

**ロールバック:**
```bash
<私有リポジトリの運用スクリプト>/lambda-rollback.sh CareQuestStack
```

### 2.6 CQ-05: Lambda コールドスタート遅延

**検知:** p95レイテンシ > 800ms 継続

**対応:**
| 対策 | 実装 |
|------|------|
| Provisioned Concurrency | CDK設定追加 |
| メモリ増強 | 128MB → 256MB |
| コード最適化 | 依存関係削減 |

---

### 2.7 CQ-06: 履歴参照タイムアウト

**検知:** Query実行時間 > 3000ms

**対応:**
```bash
# DynamoDB Query Metrics確認
aws cloudwatch get-metric-statistics \
  --namespace AWS/DynamoDB \
  --metric-name QueryReturnedItemCount \
  --dimensions Name=TableName,Value=carequest-records \
  --start-time $(date -u -v-1H +%Y-%m-%dT%H:%M:%SZ) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%SZ) \
  --period 300 \
  --statistics Average
```

| 原因 | 対応 |
|------|------|
| パーティションキー偏り | GSI追加検討 |
| 大量データ取得 | ページネーション追加 |
| フィルタ条件非効率 | クエリ最適化 |
