# Care Quest 継続的改善ログ(CSI)

Last updated: 2026-07-11 JST

ITIL 継続的改善(Continual Service Improvement)の記録。バッチごとの教訓・欠陥・反映先を蓄積し、仕組みとしての改善サイクルを回す。

---

## 記録フォーマット

| フィールド | 内容 |
| --- | --- |
| バッチ | 第N バッチ |
| 差し戻し件数 | ワーカーの成果物をプランナーが差し戻した件数 |
| プランナー検出欠陥 | プランナー再検証で発見した欠陥(ワーカーの「green」報告が実際と食い違っていた等) |
| 繰り返しパターン | 複数タスク/バッチで繰り返した失敗 |
| 反映先 | 修正した SKILL / テンプレ / DoD / チェックリスト の識別子 |

## 追記ガイド(バッチ完了時)

1. バッチ完了後、delegate スキルの「バッチ完了時のふりかえり手順」に従い教訓を抽出する
2. 上記フォーマットで新しいセクションを最上部(最新バッチを先頭)に追記する
3. 繰り返しパターンが確認できたら、対応するスキルまたはワーカープロンプトテンプレを修正し、反映先に記録する
4. improvement-log.md の変更は、バッチのコミットと同一コミットに含める(教訓の揮発防止)
