# Care Quest 設計原則 — 「頑張らせない」ための知見

Last updated: 2026-07-09 JST

オーナーの方針(2026-07-09)を受けて整理した、プレッシャーを生まないプロダクト設計の知見。新機能・文言・指標を作るときは必ずここに照らす。`.claude/skills/carequest-product-tone/SKILL.md` はこの原則の実装ガイド。

## 核となる考え方

このアプリの目的は介護を「もっとやらせる」ことではなく、**「今日をそのまま認める」**こと。介護系アプリが陥りがちな失敗は、善意のゲーミフィケーションが「もっと頑張れ」という圧力装置に変わること。介護は仕事と違い「休めない・辞められない・成果が見えない」ため、一般的な生産性アプリの機構(目標、連続記録、達成率)はそのまま持ち込むと有害になる。

## なぜ「効率化」と「楽しみ」がよい指標なのか

### 効率化(介護がラクになる工夫)

- 「頑張りの量」を増やす指標は疲弊を加速するが、「同じケアをラクにする工夫」は**負荷を下げながら介護の質を保つ**。増やすことではなく減らすことを称える、数少ない安全な指標
- 工夫の記録は他の介護者への知見共有(将来の「みんな」画面)にも転用できる。「頑張り自慢」は比較を生むが、「工夫の共有」は全員を助ける

### 楽しみ・趣味(セルフケア)

- レスパイト(介護者の休息)は介護福祉の確立した概念。**介護者が自分を保つことは、持続可能な介護の前提条件**であり、サボりではない
- 「楽しんだことに罪悪感を持つ」のは家族介護者に極めて多い心理。楽しみをポイントとして正式にカウントすることは、「楽しんでいい」というアプリからの公式な許可になる。これは機能ではなくメッセージ
- 既に「自分も休憩した」(+10pt)が存在する。趣味・楽しみ・工夫はこの延長線上にあり、思想として一貫する

## プレッシャー源のチェックリスト(導入禁止・要注意の機構)

| 機構 | 判定 | 理由・代替 |
| --- | --- | --- |
| 連続記録(ストリーク) | 導入しない | 途切れた日が「失敗」になる |
| 日次目標・達成率・ノルマ | 導入しない | 未達の日が「不足」になる |
| ランキング・他者比較 | 導入しない | 介護は条件が違いすぎて比較不能 |
| レベル・ランク制 | 導入しない | 「上げ続けなければ」という圧になる |
| 記録0件の可視化 | 導入しない(実装済み) | 履歴は記録がある日だけ表示する |
| リマインド通知 | デフォルトオフ、1日1回まで | 文言は「記録して」ではなく労い |
| ポイント | 現状維持・要注意 | 「目標」ではなく「重み(意味づけ)」として使う。目標値やノルマと結合した瞬間に圧力装置になる。累計の強調より「今日の意味」を優先する |
| バッジ・実績 | 慎重に | 「集めなければ」にならない設計(回顧的な贈り物として渡すなら可)ならありうる |

## 指標設計の指針

- 測るべきは「頑張りの量」ではなく **「本人が意味を感じられたか」**(ふりかえり記入、「また使いたい」、気持ちの変化)
- 運営側の分析でも「記録数が少ないユーザー」を「離脱リスク」とだけ扱わない。記録が少ない=介護が軽い日々かもしれず、それは良いこと
- ポイントの多寡を成功指標にしない。1日1タップでも「今日を認める」が起きていれば成功

## 新機能を作るときの3つの質問

1. この機能は、疲れ切った夜の佐藤さん(ペルソナA)に「もっとやれ」と言っていないか?
2. 使わなかった日・できなかった日に、罪悪感を生む表示や通知はないか?
3. 「減らすこと・休むこと・楽しむこと」が「増やすこと」と同等以上に称えられているか?
