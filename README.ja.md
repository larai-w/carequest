# Care Quest

**家族介護者が、今日できたことを記録して振り返るためのWebアプリです。**

[アプリを開く](https://veai.jp/carequest/) · [English](README.md) · [開発への参加](CONTRIBUTING.md)

基本の記録は登録不要で、まずブラウザー内に保存します。サインインすると、任意でクラウドバックアップと復元を利用できます。画面は日本語です。診断、介護や服薬の要否の判断、臨床予測を行う機能ではありません。

## できること

- ケア項目を選んで記録し、週間の振り返りを見る。
- 体力の状態や休息モード、メモ、よかったことを残す。
- 記録や取り消しの直後に「元に戻す」で操作を戻す。
- JSONでアプリの状態を保存・取り込みし、CSVで記録を表計算向けに出力する。
- サインイン後に、ケア記録をクラウドへバックアップする。

同じ項目を短時間に続けて記録した場合は、その旨を表示します。端末への保存に失敗した場合は、保存できたと表示しません。体力に関する相談先の案内は決められた条件によるもので、リスク予測モデルではありません。

## 保存される場所と範囲

| 保存先 | 内容・制約 |
| --- | --- |
| ブラウザーの `localStorage` | 基本の記録やメモ。ブラウザーデータ削除や端末紛失で失われることがあります |
| クラウドバックアップ | ケア記録。メモ、よかったこと、体力履歴、追加したケア項目は対象外です |
| JSONファイル | クラウドより広い範囲のアプリ状態を保存・取り込みできます。端末ごとのリマインド状態は取り込み先の値を維持します |
| CSVファイル | 表計算・閲覧用の記録です。アプリへの復元形式ではありません |

サインインだけでバックアップ成功とは見なしません。アカウント画面と振り返り画面の最終バックアップ時刻・結果を確認してください。

記録の削除や取り消しはクラウドにも反映し、通信できない場合は次の同期で再試行します。クラウドの記録をまとめて削除すると自動バックアップを停止し、手動バックアップで再開します。共有端末で別アカウントに切り替えた場合は、端末の記録の所有確認が必要です。

JSONにサインイン状態やすべてのブラウザー設定が含まれるわけではありません。端末移行前に、別の場所から読めるJSONの控えを用意してください。書き出したファイルや共有済みのコピーは、アプリ内で削除しても自動では消えません。

## ローカルで動かす

Git、Node.js 24、npmを用意します。AWS認証情報は不要です。本番の環境ファイルを含まない、新しいチェックアウトを使ってください。

```bash
git clone https://github.com/larai-w/carequest.git
cd carequest
npm ci
npm run dev
```

**http://localhost:3000/carequest/** を開きます。終了は `Ctrl+C` です。

専用のブラウザープロフィールで架空の項目を記録し、「元に戻す」、再読み込み、JSON/CSV書き出しを試せます。別の検証用プロフィールへJSONを取り込むと、復元の流れを確認できます。これは実装を読むための操作例であり、今回の動作検証結果ではありません。

クラウド機能を接続する場合だけ、隔離された開発環境の設定を `.env.local` に置きます。[英語READMEの設定項目](README.md#optional-cloud-configuration)を参照してください。`NEXT_PUBLIC_` の値はブラウザーへ配信されるため、秘密鍵やトークンを入れないでください。

## 構成

```text
日本語画面（Next.js / TypeScript）
    ├─ localStorage：最初に端末へ保存
    ├─ JSON / CSV：利用者がファイル出力
    └─ 任意のクラウド機能
         Cognito認証 → API Gateway → Lambda → DynamoDB

静的配信：S3 / CloudFront
構成管理：AWS CDK（infra/）
```

Next.jsは `/carequest` をベースパスとして静的出力します。`npm run build` の出力先は `out/` です。開発は `npm run dev` を使用します。`npm start` は `next start` に対応しており、この静的出力の配信手順ではありません。

ローカル優先でも、設定したAPIに対する任意のフィードバック送信や集計表示などがあります。ネットワーク通信が一切ないという意味ではありません。

## 既存の検査を実行する

```bash
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
```

Playwrightは開発サーバーを自動起動し、ローカルに既存サーバーがあれば再利用します。本番接続したサーバーは再利用しないでください。ブラウザーのインストール時にはダウンロードが発生します。

インフラの検査は、repoのルートから次のように実行できます。

```bash
npm --prefix infra ci
npm --prefix infra test
npm --prefix infra run build
npm --prefix infra run synth
```

`synth` は構成テンプレートの生成で、デプロイではありません。検査対象とソースへのリンクは[英語README](README.md#testing)にあります。これらのコマンドの掲載は、最新の実行結果や本番稼働の保証ではありません。

## 公開・運用上の注意

**文書だけの変更でも、`main` にpushすると本番デプロイが起動します。** 手動実行と、6時間ごとの配信差分確認も設定されています。CIと本番配信は別ワークフローであるため、すべてのCI完了を待つ仕組みだと推測しないでください。

変更はブランチでレビューし、マージやインフラ変更は別の公開判断として扱います。現在の本番配信はGitHub OIDCによるAWSロール引受けを使用します。[配信の説明](docs/deploy.md)を参照してください。

公開ファイルをステージした後は、Python 3で以下を実行します。

```bash
python3 scripts/check_public_repo.py --staged
```

個人情報・認証情報・実際の介護記録をIssue、PR、サンプルに含めないでください。
